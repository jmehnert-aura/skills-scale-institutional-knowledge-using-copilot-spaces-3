# Technical Writer Onboarding Checklist

## Purpose
This checklist helps new Technical Writers quickly onboard to OctoAcme's documentation practices, tools, and workflows. Complete these items during your first 2-4 weeks.

---

## Week 1: Getting Started

### Access & Tools Setup
- [ ] Obtain access to GitHub organization and repositories
- [ ] Set up development environment (Git, code editor, etc.)
- [ ] Access documentation tools and platforms
- [ ] Join relevant Slack/Teams channels (e.g., #documentation, #releases, #engineering)
- [ ] Set up email and calendar
- [ ] Complete company onboarding requirements

### Introduction to Documentation
- [ ] Review existing documentation structure in `/docs` folder
- [ ] Read all OctoAcme process documents:
  - [ ] Project Management Overview
  - [ ] Roles and Personas
  - [ ] Project Initiation
  - [ ] Project Planning
  - [ ] Execution and Tracking
  - [ ] Release and Deployment
  - [ ] Risks and Communication
  - [ ] Retrospective and Continuous Improvement
- [ ] Review documentation style guide (if available)
- [ ] Understand documentation review and approval process

### Team Introductions
- [ ] Meet with hiring manager for role expectations and goals
- [ ] Introduction meeting with Project Manager
- [ ] Introduction meeting with Product Manager
- [ ] Introduction meeting with Release Manager
- [ ] Introduction meeting with QA Lead
- [ ] Meet key developers who will be documentation collaborators
- [ ] Shadow a documentation review session

### Understanding the Product
- [ ] Review product overview and architecture
- [ ] Understand target audience and user personas
- [ ] Review existing user-facing documentation
- [ ] Explore the product as an end user (if applicable)
- [ ] Review recent release notes to understand change patterns

---

## Week 2: Learning Workflows & Standards

### Documentation Processes
- [ ] Learn documentation workflow (draft → review → publish)
- [ ] Understand version control and branching strategy
- [ ] Learn how to create and submit documentation PRs
- [ ] Understand documentation release schedule
- [ ] Review documentation quality standards and checklists

### Tools & Technologies
- [ ] Learn Markdown formatting and conventions used
- [ ] Understand documentation generation tools (if applicable)
- [ ] Set up local preview environment for docs
- [ ] Learn screenshot and diagram creation tools
- [ ] Understand how to test documentation locally

### Collaboration Setup
- [ ] Subscribe to relevant GitHub notifications
- [ ] Set up recurring meetings:
  - [ ] Weekly sync with Product Manager
  - [ ] Weekly sync with development team
  - [ ] Release coordination with Release Manager
- [ ] Understand escalation path for urgent documentation needs
- [ ] Learn how to request subject matter expert (SME) reviews

### Content Standards
- [ ] Review voice and tone guidelines
- [ ] Understand terminology and glossary standards
- [ ] Learn formatting conventions (headings, lists, code blocks)
- [ ] Study examples of high-quality documentation
- [ ] Understand accessibility requirements for documentation

---

## Week 3: First Contributions

### Initial Documentation Tasks
- [ ] Fix 2-3 small documentation issues (typos, broken links, clarity improvements)
- [ ] Submit first documentation PR and go through review process
- [ ] Update one existing document based on recent changes
- [ ] Create or update one diagram or visual aid
- [ ] Participate in a documentation review as a reviewer

### Feature Documentation Practice
- [ ] Shadow a feature kickoff meeting
- [ ] Review a feature specification from Product Manager
- [ ] Draft documentation outline for an upcoming feature
- [ ] Coordinate with developer for technical details
- [ ] Submit draft for review and incorporate feedback

### Process Participation
- [ ] Attend sprint planning or backlog refinement meeting
- [ ] Participate in release planning discussion
- [ ] Observe a QA sign-off meeting
- [ ] Shadow Release Manager during a deployment

---

## Week 4: Integration & Ownership

### Taking Ownership
- [ ] Identify 2-3 documentation areas to own and maintain
- [ ] Create a documentation improvement backlog
- [ ] Set up documentation quality metrics tracking
- [ ] Propose one documentation process improvement

### Release Documentation
- [ ] Review Release Manager checklist requirements for documentation
- [ ] Understand pre-release documentation deadlines
- [ ] Learn release notes format and requirements
- [ ] Practice drafting release notes from feature PRs
- [ ] Coordinate with Release Manager on upcoming release

### Cross-functional Collaboration
- [ ] Attend retrospective meeting and capture action items
- [ ] Participate in Project Manager's status update
- [ ] Share documentation updates with Stakeholder Liaison
- [ ] Collaborate with QA Lead on test documentation

### Continuous Learning
- [ ] Identify knowledge gaps and create learning plan
- [ ] Request additional training if needed (tools, product areas, etc.)
- [ ] Set 30-60-90 day goals with manager
- [ ] Join documentation community of practice (if available)

---

## Ongoing Responsibilities (After First Month)

### Daily/Weekly Activities
- [ ] Monitor documentation-related GitHub issues and PRs
- [ ] Review and update documentation based on code changes
- [ ] Participate in team meetings and document action items
- [ ] Respond to documentation questions and requests

### Per-Release Activities
- [ ] Review feature specifications early in development
- [ ] Draft feature documentation during development
- [ ] Coordinate with developers for technical accuracy
- [ ] Submit documentation PRs before code freeze
- [ ] Get final review and sign-off from Release Manager
- [ ] Publish documentation alongside release

### Monthly Activities
- [ ] Review documentation metrics and identify improvements
- [ ] Update process documentation based on workflow changes
- [ ] Conduct documentation audits for accuracy and freshness
- [ ] Share documentation updates in team meetings

### Quarterly Activities
- [ ] Conduct major documentation review and cleanup
- [ ] Gather user feedback on documentation quality
- [ ] Propose and implement documentation improvements
- [ ] Update style guide and standards as needed

---

## Key Collaboration Points

### With Developers
- **Purpose**: Gather technical details, review accuracy, understand implementation
- **Frequency**: Daily during feature development, weekly for maintenance
- **Communication**: PR reviews, Slack messages, scheduled syncs

### With Product Manager
- **Purpose**: Understand feature goals, user scenarios, and acceptance criteria
- **Frequency**: Weekly syncs, ad-hoc for new features
- **Communication**: Feature specs, user story reviews, documentation outlines

### With Release Manager
- **Purpose**: Ensure documentation is ready before releases
- **Frequency**: Weekly during release cycles, pre-release sign-offs
- **Communication**: Release checklists, documentation status, release notes

### With QA Lead
- **Purpose**: Ensure documentation matches actual behavior and covers test scenarios
- **Frequency**: During testing phases, as needed
- **Communication**: Bug reports, acceptance criteria validation

### With Project Manager
- **Purpose**: Update process documentation, maintain project artifacts
- **Frequency**: Monthly or per-project
- **Communication**: Status updates, retrospective action items

### With Stakeholder Liaison
- **Purpose**: Understand stakeholder needs, publish stakeholder-facing docs
- **Frequency**: Monthly or as needed
- **Communication**: Stakeholder reports, external documentation

## Success Indicators

### First 30 Days
- Successfully submitted 5+ documentation PRs
- Attended all key team meetings and introductions
- Understood documentation workflow and tools
- Able to independently create simple documentation updates

### First 60 Days
- Owned documentation for 1-2 product areas
- Successfully documented a full feature from start to release
- Proactively identified and fixed documentation issues
- Built effective working relationships with key collaborators

### First 90 Days
- Independently managing documentation for multiple areas
- Contributing to documentation process improvements
- Recognized by team as reliable documentation resource
- Meeting documentation quality and timeliness standards

## Tips for Success

### Communication
- Over-communicate during your first month
- Ask questions early and often
- Document answers for future reference
- Set up regular check-ins with manager and key collaborators

### Time Management
- Block time for deep documentation work
- Batch similar tasks (e.g., all reviews in one session)
- Respect deadlines, especially pre-release timelines
- Communicate early if you're blocked or behind

### Quality Focus
- Accuracy is more important than speed
- Always get technical reviews from developers
- Test procedures and examples yourself
- Keep user perspective in mind

### Continuous Improvement
- Track common documentation questions to identify gaps
- Propose improvements to processes and tools
- Share learnings with the team
- Stay current with documentation best practices
